## Async rendering tuning

```88:96:/Users/fernandofrizzatti/development/workspace/decocms/casaevideo-storefront/src/setup.ts
setAsyncRenderingConfig({
  foldThreshold: 3,
  respectCmsLazy: true,
});
```

- `foldThreshold: 3` — first 3 sections render eagerly; everything below the fold defers.
- `respectCmsLazy: true` — CMS authors can mark sections eager/lazy in admin per page.

This combination keeps initial paint fast while leaving editorial control.

## Region-aware VTEX fetch

```66:86:/Users/fernandofrizzatti/development/workspace/decocms/casaevideo-storefront/src/setup.ts
const _baseFetch = createInstrumentedFetch("vtex");
const regionAwareFetch: typeof fetch = (input, init) => {
  const ctx = RequestContext.current;
  if (ctx) {
    const cookies = ctx.request.headers.get("cookie") ?? "";
    const segMatch = cookies.match(/(?:^|;\s*)vtex_segment=([^;]+)/);
    if (segMatch?.[1]) {
      const existingHeaders = init?.headers as Record<string, string> | undefined;
      if (!existingHeaders?.["cookie"]) {
        init = { ...init, headers: { ...existingHeaders, cookie: `vtex_segment=${segMatch[1]}` } };
      }
    }
  }
  return _baseFetch(input, init);
};
setVtexFetch(regionAwareFetch);
```

**Why**: legacy catalog calls don't go through `vtexFetch`'s cookie injection. Without this wrapper, server-side renders for a São Paulo user use the default region (Rio), then client-side hydration corrects to São Paulo — a hydration mismatch + wrong PDP availability.

**The pattern**: read `vtex_segment` from `RequestContext.current.request.headers`, inject it into the outbound `cookie` header (only if the caller hasn't supplied their own).

## PDP enrichment for cross-product variants

```29:52:/Users/fernandofrizzatti/development/workspace/decocms/casaevideo-storefront/src/setup/commerce-loaders.ts
// Wrap PDP to fetch similar products (color/voltage variants) when CMS
// configures "similars: true". Without this, isSimilarTo is empty and
// the variant selector won't show cross-product options (e.g. Cor: Verde/Preto).
export const cachedPDP = async (props: any) => {
  const page = await _basePDP(props);
  if (!page?.product || props.similars === false) return page;
  const enriched = await withIsSimilarTo(page.product);
  return { ...page, product: enriched };
};
// ...
  "vtex/loaders/intelligentSearch/productDetailsPage.ts": cachedPDP,
```

**Why**: Casa's PDP shows "Cor: Verde / Preto" cross-product variants. The default PDP loader doesn't fill `isSimilarTo`, so the variant selector renders blank. Wrapping `cachedPDP` adds a second fetch only when the CMS opts in (`similars: true`).

**The pattern**: don't fork inline loaders — wrap them, and re-register under the same `__resolveType` key.

## A/B testing + KV-backed redirects

```105:123:/Users/fernandofrizzatti/development/workspace/decocms/casaevideo-storefront/src/worker-entry.ts
export default withABTesting(decoWorker, {
  kvBinding: "SITES_KV",
  preHandler: (request, url) => {
    const redirect = matchRedirect(url.pathname, cmsRedirects);
    if (redirect) {
      const target = url.search ? `${redirect.to}${url.search}` : redirect.to;
      return new Response(null, {
        status: redirect.status,
        headers: { Location: target },
      });
    }
    return null;
  },
```

Two things composed:

1. **`withABTesting`** wraps the entire decoWorker — variant assignment + sticky session.
2. **`preHandler`** runs CMS-defined redirects before A/B kicks in, so legacy URLs forward consistently regardless of variant.

Order matters: redirects first means `/old-url` 301s to `/new-url` for both control and canary.

```13:31:/Users/fernandofrizzatti/development/workspace/decocms/casaevideo-storefront/src/cache-config.ts
setCacheProfile("static", {

  browser: { fresh: 300, swr: 3600, sie: 14400 },
  client: { staleTime: 600_000, gcTime: 3_600_000 },

// ...
setCacheProfile("listing", {
  edge: { fresh: 300, swr: 1800, sie: 7200 },
```

Casa's profile choices reflect their traffic mix:

- **`static`** (home, brand pages): 30 min fresh, 2 hr SWR. Long because home content rarely changes.
- **`listing`** (PLP): 5 min fresh, 30 min SWR. Tighter because product availability changes during business hours.

Tune based on your actual content velocity.

## VTEX checkout proxy

Casa's worker entry includes a custom VTEX checkout proxy with HTML transforms (deferring scripts, cookie expiry adjustment). The pattern:

```ts
import { createVtexCheckoutProxy } from "@decocms/apps/vtex/middleware";

const proxyHandler = createVtexCheckoutProxy({
  checkoutOrigin: "https://www.casaevideo.com.br",
  htmlTransform: (html) => html.replace(/<script>/g, "<script defer>"),
  cookieExpiryPaths: { "checkout.vtex.com__orderFormId": 24 * 60 * 60 },
});
```

Reach for this when VTEX's hosted checkout doesn't exactly match your site's UX or perf needs.

## Site SEO via `configureWebsite`

```ts

configureWebsite({ seo: getSiteSeo() });
```

Wires the Site block's SEO config (title, description, OG, robots) into the framework's head builder. Without this, you'd have to render SEO tags manually in `__root.tsx`.

## What to take from Casa

- **Region-aware fetch** if you have regional availability/pricing.
- **`setAsyncRenderingConfig`** with a tuned `foldThreshold`.
- **`withABTesting` + KV** when you outgrow CMS matchers.
- **`setCacheProfile`** when default TTLs don't match your content velocity.
- **Wrap, don't fork** inline loaders.

## What NOT to copy verbatim

- The Deno-orchestrated `start` script — only relevant if you're orchestrating local dev with Deco CLI tooling.
- The Sentry/Firebase wiring — site-specific, not framework-canonical.
- Casa's specific cache TTLs — tune for your traffic.
