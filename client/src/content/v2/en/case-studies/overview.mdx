Three deco.cx v2 storefronts run in production today. They share a common spine but each makes different tradeoffs around caching, A/B testing, redirects, region handling, and observability. Reading these case studies side-by-side is a fast way to learn which knob exists for which problem.

## The three

| Site | Brand | Role in this docs |
|---|---|---|
| **Casa&Video** | Brazilian electronics retailer | The "kitchen sink" reference — every framework feature in use |
| **Bagaggio** | Brazilian luggage and travel retailer | The "lean and pruned" reference — minimum surface area, decofile-pruned loaders |
| **Le biscuit** | Brazilian home goods retailer | The "spine" reference — closest to defaults, useful starting point |

Each has a dedicated page below.

## What's the same across all three

Every reference site uses the same architectural spine:

- **Vite plugin order**: Cloudflare → TanStack Start → React (compiler) → Tailwind v4 → `decoVitePlugin`.
- **`setup.ts` shape**: `createSiteSetup` with sections glob, blocks, sections.gen, applySectionConventions, registerCommerceLoaders, setInvokeLoaders.
- **Worker entry**: `import "./setup"` first, `createDecoWorkerEntry`, admin handlers wired.
- **Routes**: `cmsRouteConfig` for catch-all, `cmsHomeRouteConfig` for home, both with `ignoreSearchParams: ["skuId"]`.
- **Commerce**: VTEX via `@decocms/apps/vtex`, with `initVtexFromBlocks` + `setVtexFetch(createInstrumentedFetch("vtex"))`.
- **Caching**: edge profiles with default TTLs, occasional `setCacheProfile` overrides.
- **Build**: `generate:blocks`, `generate:schema`, `generate:sections`, `generate:loaders`, `tsr generate`, `vite build`, `wrangler deploy`.

If you take nothing else from these case studies, take the spine.

## What's different

The differences fall into a few categories.

### Root layout

| Site | Pattern |
|---|---|
| Casa&Video | `DecoRootLayout` from `@decocms/start/hooks` |
| Le biscuit | `DecoRootLayout` from `@decocms/start/hooks` |
| Bagaggio | Custom `RootLayout` with bespoke font loading + minicart drawer |

Use `DecoRootLayout` unless you need control the framework shell can't give.

### Async rendering

| Site | Config |
|---|---|
| Casa&Video | `setAsyncRenderingConfig({ foldThreshold: 3, respectCmsLazy: true })` |
| Le biscuit | (default) |
| Bagaggio | (default) |

Casa&Video's perf tuning is in the [Casa&Video case study](/v2/en/case-studies/casaevideo).

### VTEX fetch wrapping

| Site | Pattern |
|---|---|
| Casa&Video | Region-aware: injects `vtex_segment` cookie into legacy fetch calls |
| Le biscuit | Region-aware (same pattern as Casa) |
| Bagaggio | Plain `createInstrumentedFetch("vtex")` |

The region-aware wrapper matters when your store has region-specific availability or pricing.

### Redirects

| Site | Pattern |
|---|---|
| Casa&Video | CMS-driven via `loadRedirects(loadBlocks())` |
| Le biscuit | Same |
| Bagaggio | CSV-driven (`redirect.csv?raw` import + custom parser) |

Bagaggio's CSV pattern is the [legacy-URL-migration template](/v2/en/case-studies/baggagio).

### A/B testing

| Site | Pattern |
|---|---|
| Casa&Video | `withABTesting` + `SITES_KV` |
| Le biscuit | `withABTesting` + `SITES_KV` |
| Bagaggio | None (no AB harness in worker; KV bind commented) |

Worker-level A/B is opt-in. Add it only when you need full-stack experiments.

### Cache profile overrides

| Site | Custom profiles |
|---|---|
| Casa&Video | Aggressive: looser `static`, tighter `search`, bespoke `listing` |
| Le biscuit | Mostly default |
| Bagaggio | Sitemap routed to `static`; otherwise default |

Casa's profile choices reflect their traffic mix. Yours will probably be different.

### `withSiteGlobals`

| Site | Pattern |
|---|---|
| Casa&Video | Not used |
| Le biscuit | Not used |
| Bagaggio | Wraps `cmsRouteConfig` to inject site-wide globals |

Useful when you want the same head tags on every CMS route without copy-paste.

### Loader pruning

| Site | Strategy |
|---|---|
| Casa&Video | Long explicit `--exclude` list in `generate:loaders` |
| Le biscuit | Long explicit `--exclude` list |
| Bagaggio | Decofile-pruned: `--decofile-dir .deco/blocks` |

Bagaggio's pattern is leaner — only loaders the CMS actually references appear in `loaders.gen.ts`. Recommended for new sites.

## Read order

Pick the case study that matches your scenario:

- **Building a new storefront from scratch** → start with [Le biscuit](/v2/en/case-studies/lebiscuit).
- **Migrating a complex Fresh site with a lot of legacy URLs** → [Bagaggio](/v2/en/case-studies/baggagio).
- **Optimizing an established storefront for performance, regional correctness, or A/B testing** → [Casa&Video](/v2/en/case-studies/casaevideo).

## A note on these references

These three storefronts are **read-only references** in this docs site. They're real production sites; we cite their code as canonical patterns but don't expect them to track every framework change in lockstep with the package.

When you cite a pattern from these sites in your own code, link the file path so future readers can see the original context.
