A short reference for the vocabulary that shows up across these docs. Where a term has a dedicated page, the term links to it.

## A

### Action

A server-side function that **mutates** state — adding to cart, signing in, sending an email. Mirror of a [loader](#loader) but for writes. Lives under `vtex/actions/`, `shopify/actions/`, etc. See [VTEX loaders and actions](/v2/en/commerce/vtex-loaders-and-actions).

### Admin

[`admin.deco.cx`](https://admin.deco.cx) — the editor where content authors edit pages, sections, and blocks. Talks to your storefront via the [admin protocol](/v2/en/concepts/admin-protocol).

### Admin protocol

The HTTP contract between admin and a storefront: `/live/_meta`, `/.decofile`, `/deco/render`, `/deco/invoke`. See [Admin protocol](/v2/en/concepts/admin-protocol).

### App

A pluggable integration with a third-party service. VTEX, Shopify, Resend, and Website are all "apps". See [Commerce overview](/v2/en/commerce/overview).

## B

### Block

A JSON document with a `__resolveType` field. Pages, sections, app configs, matchers, loaders are all blocks. See [Blocks](/v2/en/concepts/blocks).

### `blocks.gen.json`

The generated bundle of all `.deco/blocks/*.json` content, loaded at runtime. Generated by `generate-blocks`.

### `blocks.gen.ts`

A re-export of `blocks.gen.json`. The [Vite plugin](/v2/en/framework/vite-plugin) replaces this with a fast `JSON.parse` at load time.

## C

### Cache profile

A named set of cache TTLs (edge `s-maxage`, browser `max-age`, SWR window). The framework auto-detects a profile by URL. See [Caching strategy](/v2/en/deployment/caching-strategy).

### `cachedLoader`

A wrapper that adds in-flight dedup, SWR, and TTL-by-status to any loader. See [Caching](/v2/en/framework/caching).

### Catch-all route

`src/routes/$.tsx` — handles every URL not matched by a more specific route. Backed by `cmsRouteConfig`. See [Pages and routes](/v2/en/concepts/pages-and-routes).

### `cmsRouteConfig` / `cmsHomeRouteConfig`

TanStack Router configs that wire CMS resolution into route loaders. See [Routes](/v2/en/framework/routes).

### `createDecoWorkerEntry`

The outermost wrapper around your Cloudflare Worker. Runs admin routes, cache, and static asset bypass before the framework. See [Worker entry](/v2/en/framework/worker-entry).

### `createSiteSetup`

The single function call that bootstraps a v2 storefront. See [Setup](/v2/en/framework/setup).

## D

### Daemon

The local dev tunnel that lets `admin.deco.cx` talk to your localhost. Started by the Vite plugin in dev mode.

### Decofile

The complete set of blocks for a site. Lives in `.deco/blocks/`, served at `/.decofile`.

### Deferred section

A section that renders a placeholder server-side and hydrates on scroll. See [Deferred rendering](/v2/en/concepts/deferred-rendering).

### `defineTool`

The pattern for declaring a typed, auditable tool — used in `@decocms/blocks` for admin handlers. Most app users don't author tools directly.

## E

### ETag

A content hash used by `/live/_meta` and `/.decofile` so admin can cache responses. The framework uses DJB2 over the content.

### Edge cache

Cloudflare's `caches.default` — the regional cache layer between users and your Worker. The framework reads/writes here automatically. See [Caching strategy](/v2/en/deployment/caching-strategy).

### `expectedOrderFormSections`

The list of VTEX `orderForm` sections requested by a cart loader/action. The cart server-side and `useCart` client-side must request the same list. See [VTEX gotchas](/v2/en/commerce/vtex-gotchas).

## F

### `foldThreshold`

In `setAsyncRenderingConfig`, the index of the first deferred section. Sections [0..foldThreshold) render eagerly. See [Deferred rendering](/v2/en/concepts/deferred-rendering).

## I

### Inline loader

A CMS-shaped loader that composes multiple low-level fetches into one page payload (PDP, PLP, shelf, search). See [VTEX inline loaders](/v2/en/commerce/vtex-inline-loaders).

### `instrumentedFetch`

A `fetch` wrapper with OpenTelemetry tracing, metrics, and Server-Timing. Use in loaders. See [Caching](/v2/en/framework/caching).

### `invoke`

The mechanism for calling a loader/action over HTTP at `/deco/invoke`. The generated typed client is `invoke.gen.ts`. See [Invoke](/v2/en/framework/invoke).

### Islands

The Fresh/Preact pattern of selectively-hydrated components. **Doesn't exist in v2** — replaced with React `"use client"` boundaries and Server Components. See [Migration playbook](/v2/en/migration/playbook).

## L

### `LazySection`

The component that wraps deferred sections. Renders a placeholder + IntersectionObserver. See [Deferred rendering](/v2/en/concepts/deferred-rendering).

### `LiveControls`

A script that lets admin's preview iframe communicate with the storefront. Hover-highlight, click-to-source. See [Hooks](/v2/en/framework/hooks).

### Loader

A server-side function that **reads** state. Two flavors: section-colocated (returns props for the section) or top-level (exposed via `/deco/invoke`). See [Loaders](/v2/en/concepts/loaders).

### `loadCmsPage`

The function that resolves a CMS page from `siteName + pathname`. Called by `cmsRouteConfig`'s loader. See [Routes](/v2/en/framework/routes).

### `loadDeferredSection`

The TanStack Start server function that hydrates a deferred section on scroll. Called by `LazySection`. See [Deferred rendering](/v2/en/concepts/deferred-rendering).

## M

### Manifest

The registry of section IDs, loader IDs, action IDs, and app IDs available to the CMS. Part of `/live/_meta`.

### Matcher

A function that returns true/false based on the request, used inside multivariate blocks. See [Matchers and flags](/v2/en/concepts/matchers-and-flags).

### `meta.gen.json`

The JSON Schema bundle generated from your section TS types. Served at `/live/_meta`. Generated by `generate-schema`.

### Multivariate block

A block that swaps based on a matcher's verdict — the core A/B / targeting primitive. See [Matchers and flags](/v2/en/concepts/matchers-and-flags).

## P

### Page

A block of `__resolveType: "$live/pages/Page.ts"` with a `path` and a `sections` array. The CMS routes URLs to pages.

### `pageType`

VTEX's classification of a URL: `Department`, `Category`, `Brand`, `Product`, etc. Drives PLP routing. See [VTEX loaders and actions](/v2/en/commerce/vtex-loaders-and-actions).

### Profile (cache)

See [Cache profile](#cache-profile).

## R

### `RequestContext`

The AsyncLocalStorage-backed per-request state, available server-side. Reads cookies, env, request headers. See [Loaders](/v2/en/concepts/loaders).

### `resolveDecoPage`

The internal function that resolves a page block's section list into a renderable tree. Called by `loadCmsPage`.

## S

### Sales channel

VTEX-specific concept: a numbered slot for products + prices + currency. Default `"1"`. See [VTEX gotchas](/v2/en/commerce/vtex-gotchas).

### Section

A React component the CMS can render on a page. Lives under `src/sections/`. See [Sections](/v2/en/concepts/sections).

### Segment

A key-value object mixed into the cache key for response variation (device, region, user state). Built by `buildSegment` in `createDecoWorkerEntry`. See [Worker entry](/v2/en/framework/worker-entry).

### `setAsyncRenderingConfig`

Configures the deferred-rendering strategy: fold threshold, CMS lazy respect, always-eager kinds. See [Deferred rendering](/v2/en/concepts/deferred-rendering).

### `setCacheProfile`

Overrides a cache profile's TTLs. See [Caching strategy](/v2/en/deployment/caching-strategy).

### `setVtexFetch`

Replaces the global VTEX fetch with a wrapped version (instrumented, region-aware). See [VTEX overview](/v2/en/commerce/vtex-overview).

### `siteName`

The identifier used by `admin.deco.cx` to identify your storefront. Match what's in admin's settings.

### Slug cache

The map from product slug → canonical SKU, used to skip a round-trip on PDP. See [VTEX gotchas](/v2/en/commerce/vtex-gotchas).

### SWR (stale-while-revalidate)

The pattern of serving stale cached data immediately while a background revalidation runs. The framework uses it at every cache layer.

## T

### TanStack Start

The full-stack React framework v2 is built on. Replaces Fresh in v1.

## V

### Vite plugin

`decoVitePlugin()` from `@decocms/tanstack/vite`. Required in every site's Vite config. Handles `blocks.gen` fast-path, server stubs, dev daemon. See [Vite plugin](/v2/en/framework/vite-plugin).

### `vtex_segment`

The cookie that conveys a VTEX user's region, sales channel, and currency. Critical for regional commerce — must propagate from inbound request to upstream calls. See [VTEX client and middleware](/v2/en/commerce/vtex-client-and-middleware).

## W

### Widget

A typed annotation in `@decocms/blocks/types/widgets` that tells the schema generator to render a custom admin UI control (image picker, color picker, rich text editor). See [Sections](/v2/en/concepts/sections).

### `withABTesting`

Worker wrapper for site-version A/B testing. See [A/B testing and redirects](/v2/en/deployment/ab-testing-and-redirects).

### `withSiteGlobals`

Wraps a route config with site-wide globals (analytics IDs, theme tokens). See [Routes](/v2/en/framework/routes).

### Worker entry

`src/worker-entry.ts` — the file Cloudflare loads. Wraps the TanStack server entry with `createDecoWorkerEntry`. See [Worker entry](/v2/en/framework/worker-entry).

### `wrangler.jsonc`

The Cloudflare Workers config file. See [Cloudflare Workers deployment](/v2/en/deployment/cloudflare-workers).
