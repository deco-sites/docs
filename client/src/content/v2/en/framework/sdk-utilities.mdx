The SDK is a grab-bag of small utilities the framework exposes for use inside sections, loaders, and worker code. Most are tiny; collectively they save a lot of boilerplate. This page is the index.

<Callout type="warning">
**Subpath imports vs. barrel.** Several utilities have their own `package.json` export but are NOT re-exported from the `@decocms/start/sdk` barrel. Flagged below as "subpath only". Always use the subpath form for these.
</Callout>

## Scripts and DOM glue

### `useScript`

```ts
import { useScript, inlineScript } from "@decocms/start/sdk/useScript";
```

Two patterns:

- **`useScript(fn)`** — extract a function to an inline `<script>` tag. **Discouraged in v2** because hydration interactions are fragile. Migrate to `inlineScript` or move to a real client component.
- **`inlineScript(string)`** — inject a static script string. Safe for analytics snippets and feature detection.

```tsx
<head>
  {inlineScript(`window.dataLayer = window.dataLayer || [];`)}
</head>
```

### `signal` (subpath only)

```ts
import { signal } from "@decocms/start/sdk/signal";
```

Lightweight `@tanstack/store`-backed signal. v1 sites that used `@preact/signals` map their signal usage to this.

```ts
const cartCount = signal(0);

cartCount.value++;
console.log(cartCount.value);
```

For most React components, prefer `@tanstack/store` directly with `useStore`.

## Class names

### `clx` (barrel)

```ts
import { clx } from "@decocms/start/sdk/clx";
```

Conditional class joiner. Like `clsx`:

```tsx
<div class={clx("base", isActive && "active", { highlighted })} />
```

### `cn` (subpath only)

```ts
import { cn } from "@decocms/start/sdk/cn";
```

`clx` plus `tailwind-merge`. Resolves Tailwind class conflicts:

```tsx
<div class={cn("p-4 p-8", isLarge && "p-12")} />
// → "p-12"
```

Use `cn` when you have variant overrides; use `clx` when you don't.

## Encoding & crypto

### `encoding` (subpath only)

```ts
import { toBase64, fromBase64 } from "@decocms/start/sdk/encoding";
```

Base64 encoding that produces output **compatible with `btoa()` padding** — the admin uses `btoa()` for definition refs, so the encoder must match exactly.

### `crypto` (subpath only)

```ts
import { djb2 } from "@decocms/start/sdk/crypto";
```

DJB2 content hash, used for ETags. Not cryptographically secure — fast hash for cache invariants.

## HTTP & retry

### `http` (subpath only)

```ts
import { httpClient } from "@decocms/start/sdk/http";
```

Thin `fetch` wrapper with sane defaults (timeouts, JSON parsing, error normalization). Most sites use [`createInstrumentedFetch`](/v2/en/framework/caching#instrumentedfetch-and-caching) instead.

### `retry` (subpath only)

```ts
import { retry } from "@decocms/start/sdk/retry";
```

Exponential-backoff retry helper for flaky upstreams.

```ts
const result = await retry(() => fetchSomething(), { attempts: 3, delay: 200 });
```

## Cookies

### `cookie` (barrel)

```ts
import { parseCookies, setCookieHeader } from "@decocms/start/sdk/cookie";
```

Parse `Cookie` headers into objects; build `Set-Cookie` strings.

### `cookiePassthrough` (barrel + subpath)

```ts
import { passthroughCookies } from "@decocms/start/sdk/cookiePassthrough";
```

Helper for forwarding inbound cookies to upstream APIs. Used internally by `@decocms/apps/vtex` middleware.

## CSP & redirects

### `csp` (barrel)

```ts
import { buildCsp } from "@decocms/start/sdk/csp";
```

Construct Content-Security-Policy headers programmatically. Useful when your CSP varies by route or includes nonces.

### `redirects` (barrel)

```ts
import { loadRedirects, matchRedirect, addRedirects } from "@decocms/start/sdk/redirects";
```

Load redirects from blocks (CMS-defined) or programmatically:

```ts
const cmsRedirects = loadRedirects(loadBlocks());
const redirect = matchRedirect("/old-path", cmsRedirects);
```

For sites with thousands of legacy redirects, add CSV-imported redirects on top:

```ts
import redirectsCsv from "../redirect.csv?raw";
import { addRedirects, parseSemicolonRedirectsCsv } from "@decocms/start/sdk/redirects";

addRedirects(parseSemicolonRedirectsCsv(redirectsCsv));
```

## Sitemap

### `sitemap` (subpath only)

```ts
import { generateSitemap } from "@decocms/start/sdk/sitemap";
```

Build a `sitemap.xml` from page blocks plus custom URLs.

```ts
return generateSitemap({
  baseUrl: "https://my-store.com",
  pages: pageUrls,
});
```

## Server timings

### `serverTimings` (barrel)

```ts
import { measure, getTimings } from "@decocms/start/sdk/serverTimings";
```

Per-request timing collector. Use inside loaders to record sub-operations:

```ts
const products = await measure("fetchProducts", () => fetchProducts());
```

The framework adds collected timings to the `Server-Timing` response header automatically.

### `abTesting` (subpath only)

import { withABTesting } from "@decocms/start/sdk/abTesting";

Worker wrapper for site-version A/B. See [A/B testing and redirects](/v2/en/deployment/ab-testing-and-redirects).

## Routing helpers

### `router` (subpath only)

```ts
import { router } from "@decocms/start/sdk/router";
```

Helper around TanStack Router for handling preload errors and graceful fallbacks. Used internally by `cmsRouteConfig`.

## URL utilities

### `urlUtils` (barrel)

```ts
import { canonicalUrl } from "@decocms/start/sdk/urlUtils";
```

URL canonicalization — used by the cache key builder and SEO components.

### `normalizeUrls` (barrel)

```ts
import { normalizeUrls } from "@decocms/start/sdk/normalizeUrls";
```

Bulk URL normalization. Strips known tracking params, normalizes trailing slashes, lowercases the host.

## Error wrapping

### `wrapCaughtErrors` (barrel)

```ts
import { wrapCaughtErrors } from "@decocms/start/sdk/wrapCaughtErrors";
```

Wraps an async function so thrown errors carry a useful stack trace through the framework's error boundaries.

## Hydration

### `useHydrated` (barrel + via hooks)

```ts
import { useHydrated } from "@decocms/start/sdk/useHydrated";
```

Boolean — true after first client render. See [Hooks](/v2/en/framework/hooks).

### `useId` (subpath)

```ts
import { useId } from "@decocms/start/sdk/useId";
```

SSR-stable ID generator. Use when you need a unique element id that matches between server and client renders.

## Device

### `useDevice` (barrel)

```ts
import { useDevice, detectDevice } from "@decocms/start/sdk/useDevice";
```

Returns request-derived device classification. See [Hooks](/v2/en/framework/hooks).

## OTel

### `otel` (subpath only)

```ts
import { initTelemetry } from "@decocms/start/sdk/otel";
```

OpenTelemetry initialization for the Worker. Auto-wired when `@microlabs/otel-cf-workers` is installed and `OTEL_*` env vars are set. See [Observability](/v2/en/deployment/observability).

## RequestContext

### `requestContext` (barrel)

```ts
import { RequestContext } from "@decocms/start/sdk/requestContext";

const ctx = RequestContext.current;
const env = ctx?.env;
const request = ctx?.request;
```

AsyncLocalStorage-backed request context. Available in any code that runs during a request — loaders, sections, server functions, custom middleware.

## Suggestions

### `useSuggestions` (subpath only)

```ts
import { useSuggestions } from "@decocms/start/sdk/useSuggestions";
```

Debounced search suggestion hook. Use in autocomplete components. Drops a fetch when input changes faster than the debounce.

## Codegen scripts

The framework ships several scripts under `@decocms/start/scripts/`:

| Script | Purpose |
|---|---|
| `generate-blocks` | Walk `.deco/blocks/` → `blocks.gen.json` |
| `generate-schema` | Extract section `Props` → `meta.gen.json` (JSON Schema) |
| `generate-invoke` | Build typed `invoke.gen.ts` client |
| `migrate` | Fresh → TanStack migration ([Migrate script](/v2/en/migration/migrate-script)) |
| `migrate-post-cleanup` | Post-migration cleanup of leftover boilerplate |
| `tailwind-lint` | Tailwind v3 → v4 lint/fix |

Invoke them via `npx tsx node_modules/@decocms/start/scripts/<name>.ts` or via npm scripts in your `package.json`. Wire them as composite scripts (e.g. `"generate": "npm run generate:blocks && npm run generate:schema && npm run generate:sections && npm run generate:loaders"`) so a single command keeps everything in sync.

## Types and widgets

### `types` (subpath)

```ts
import type { Section, App, FnContext, SectionProps } from "@decocms/start/types";
```

Shared TypeScript types — `Section` for section components, `App` for app definitions, `FnContext` for loaders/actions.

### `types/widgets` (subpath)

```ts
import type {
  ImageWidget,
  RichText,
  Color,
  ButtonGroupWidget,
  HTMLWidget,
} from "@decocms/start/types/widgets";
```

Widget types that the schema generator translates into custom admin UI controls. Use in section `Props`:

```ts
export interface Props {
  hero: ImageWidget;       // asset picker
  body: RichText;          // rich text editor
  brand: Color;            // color picker
}
```
