This page is the index of the framework packages. Each section links to a deeper reference. If you're unsure where to look, scan this page first.

<Callout type="info">
**The framework is a monorepo, not one package.** The former single `@decocms/start` package was split into focused packages with real boundaries, so no package bundles another's compiled output. Pick the binding that matches your app — `@decocms/tanstack` (TanStack Start + Cloudflare Workers) or `@decocms/nextjs` (Next.js App Router) — both compose the same `@decocms/blocks` core.
</Callout>

## The packages

| Package | Role |
|---|---|
| `@decocms/blocks` | Framework-agnostic **CMS core**: block resolution, section/loader registry, matchers, flags, middleware, hooks, and the SDK. Zero framework deps. |
| `@decocms/blocks-admin` | **Admin protocol** handlers (`/live/_meta`, `/.decofile`, `/deco/render`, `/deco/invoke`) + `createAdminSetup`. |
| `@decocms/blocks-cli` | **Code generation** (`generate`, `generate-blocks`, `generate-schema`, `generate-invoke`) + migration CLIs. |
| `@decocms/tanstack` | **TanStack Start + Cloudflare Workers** binding: worker entry, CMS routes, Vite plugin, deferred sections, KV fast deploy. |
| `@decocms/nextjs` | **Next.js App Router** binding: RSC pages, previews, route handlers, one-call setup. |
| `@decocms/apps-*` | **Commerce & website** integrations (VTEX, Shopify, Magento, Salesforce, Algolia, Resend, blog, shared commerce types). |

## What the core gives you

`@decocms/blocks` (plus a binding) exposes:

- A **CMS bridge** that resolves blocks into rendered React trees.
- A **section/loader registry** with TS → JSON Schema generation.
- A small **SDK** (caching, invoke, instrumented fetch, scripts, signals, cookies, etc.).
- **Middleware, matchers, and flags** for request-scoped behavior.

The binding adds the framework-specific glue:

- **`@decocms/tanstack`** — a **worker entry wrapper** (`createDecoWorkerEntry`) that runs admin routes, edge cache, and static asset bypass; the **CMS routes** (`cmsRouteConfig`); and the **Vite plugin** (`decoVitePlugin`) for the `blocks.gen` JSON fast-path.
- **`@decocms/nextjs`** — App Router **route handlers**, the RSC **preview page**, and `createNextSetup`.

The **admin protocol** implementation lives in `@decocms/blocks-admin`; **code generation** lives in `@decocms/blocks-cli`.

## Package exports overview

The most-used entry points across packages:

| Import | What it is |
|---|---|
| `@decocms/blocks/setup` | `createSiteSetup` |
| `@decocms/blocks/cms` | Block loading, section/loader registry, resolveDecoPage |
| `@decocms/blocks/hooks` | `DecoPageRenderer`, `LazySection`, etc. |
| `@decocms/blocks/middleware` | Observability, decoState, hydration context |
| `@decocms/blocks/sdk` | Caching, invoke, fetch, scripts, signals (barrel) |
| `@decocms/blocks/sdk/cachedLoader` | `createCachedLoader` |
| `@decocms/blocks/types` | `FnContext`, `Section`, `App` |
| `@decocms/blocks/types/widgets` | Widget types: `ImageWidget`, `RichText`, `Color`, etc. |
| `@decocms/blocks/matchers/builtins` | `MatchUserAgent`, `MatchDate`, etc. |
| `@decocms/blocks-admin` | Admin protocol handlers |
| `@decocms/blocks-admin/setup` | `createAdminSetup` |
| `@decocms/tanstack` | `cmsRouteConfig`, `loadCmsPage`, `createDecoWorkerEntry` |
| `@decocms/tanstack/vite` | `decoVitePlugin()` |

The full tables are at [Package exports reference](/v2/en/reference/package-exports).

<Callout type="warning">
**Subpath vs. barrel imports.** Several SDK utilities have their own subpath export (`@decocms/blocks/sdk/cachedLoader`, `@decocms/blocks/sdk/encoding`, `@decocms/blocks/sdk/http`, etc.) that are NOT re-exported from the `@decocms/blocks/sdk` barrel. Always use the subpath for these. The reference tables flag which are barrel-only vs. subpath-only.
</Callout>

## Three-layer architecture (as a reminder)

```
Site repo                ← Components, sections, routes, styles, contexts
  ↑ depends on
@decocms/apps-*          ← Commerce: VTEX, Shopify, Resend, types, SDK
  ↑ depends on
@decocms/tanstack        ← Binding: worker entry, routes, Vite plugin, edge cache
  ↑ depends on           (or @decocms/nextjs for the App Router)
@decocms/blocks          ← Framework core: CMS resolution, registry, SDK
  ↑ runs on
TanStack Start + React 19 + Cloudflare Workers  (or Next.js App Router)
```

Things the framework deliberately does **not** ship:

- Preact references or compatibility shims.
- Site-specific section maps.
- Commerce API calls (those live in `@decocms/apps-*`).
- UI components (those live in your site).

If you find yourself wanting one of these, reconsider — usually there's a layered solution.

## When you contribute
