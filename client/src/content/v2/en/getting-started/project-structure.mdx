A v2 storefront has a deliberately small surface. Most files are generated. This page walks the layout you'll see after cloning a reference site.

## Top-level layout

```
my-store/
├── .deco/
│   └── blocks/                # CMS content as JSON (committed)
├── public/                    # Static assets served as-is
├── scripts/                   # Site-specific tooling
├── src/
│   ├── components/            # React UI primitives (shared across sections)
│   ├── sections/              # CMS-renderable React components
│   ├── routes/                # TanStack Router file-based routes
│   ├── server/                # Server-side artifacts (mostly generated)
│   ├── setup/                 # Setup helpers (commerce loaders, cache config)
│   ├── setup.ts               # Site bootstrap entry point
│   ├── server.ts              # TanStack Start server entry
│   ├── worker-entry.ts        # Cloudflare Worker entry (calls createDecoWorkerEntry)
│   └── styles.css             # Tailwind entry point
├── package.json
├── tsconfig.json
├── vite.config.ts
└── wrangler.jsonc
```

Every reference storefront — [casaevideo](/Users/fernandofrizzatti/development/workspace/decocms/casaevideo-storefront), [baggagio](/Users/fernandofrizzatti/development/workspace/decocms/baggagio-tanstack), [lebiscuit](/Users/fernandofrizzatti/development/workspace/decocms/lebiscuit-tanstack) — follows this exact shape.

## `.deco/blocks/`

The CMS source of truth. One JSON file per block (page, section instance, app config, matcher). The admin syncs this directory; you commit it.

A block looks like:

```json
{
  "__resolveType": "site/sections/Hero/HeroBanner.tsx",
  "title": "Welcome",
  "image": { "url": "https://..." }
}
```

The `__resolveType` field tells the framework which section component to render and which loader (if any) to call.

## `src/sections/`

A "section" is a React component that the CMS can place on a page. The component's props are the JSON Schema that admin uses for editing.

```tsx
// minimal example
export interface Props {
  title: string;
  cta?: { label: string; href: string };
}

export default function Hero({ title, cta }: Props) {
  return (
    <section>
      <h1>{title}</h1>
      {cta && <a href={cta.href}>{cta.label}</a>}
    </section>
  );
}
```

The build pipeline scans this folder and emits a `sections.gen.ts` registry. See [Sections concept](/v2/en/concepts/sections).

## `src/routes/`

TanStack Router file-based routes. The two routes every site needs:

- **[`src/routes/index.tsx`](/Users/fernandofrizzatti/development/workspace/decocms/lebiscuit-tanstack/src/routes/index.tsx)** — homepage; uses `cmsHomeRouteConfig`.
- **[`src/routes/$.tsx`](/Users/fernandofrizzatti/development/workspace/decocms/lebiscuit-tanstack/src/routes/$.tsx)** — catch-all for CMS-driven URLs; uses `cmsRouteConfig`.

Plus typically a `src/routes/__root.tsx` for the global shell.

You can add custom routes alongside the catch-all (e.g. `/api/something.tsx`) and they'll take precedence.

## `src/server/cms/` (generated)

Three files, all generated by scripts in `@decocms/start`:

| File | Generated by | Purpose |
|---|---|---|
| `blocks.gen.ts` | `generate-blocks` | Re-exports the JSON bundle below |
| `blocks.gen.json` | `generate-blocks` | All `.deco/blocks/*.json` rolled into one |
| `meta.gen.json` | `generate-schema` | JSON Schema for the admin UI |
| `sections.gen.ts` | `generate-sections` | Registry of section default exports |
| `loaders.gen.ts` | `generate-loaders` | Site loader manifest (decofile-pruned) |
| `invoke.gen.ts` | `generate-invoke` | Typed client for `/deco/invoke` |

Don't edit these by hand. Re-run the generators when you change sections or blocks.

<Callout type="warning">
**`blocks.gen.json` can be large** (Casa&Video's is 11.6 MB). The Vite plugin replaces the `.ts` re-export with a fast `JSON.parse` of the `.json` at load time. Don't manually chunk `@decocms/start` or `@decocms/apps` — circular re-exports will crash on load.
</Callout>

## `src/setup.ts`

The site bootstrap. Calls `createSiteSetup` from `@decocms/start/setup`, glob-imports sections, registers loaders, configures matchers and commerce. **Must be imported first** in `server.ts` and `worker-entry.ts` so the registry exists before TanStack Start splits server functions.

See [Setup reference](/v2/en/framework/setup) for the full signature.

## `src/worker-entry.ts`

The Cloudflare Worker entry. Wraps the TanStack server entry with `createDecoWorkerEntry` so admin routes, cache purge, static asset bypass, and edge caching happen *before* the framework gets the request. See [Worker entry reference](/v2/en/framework/worker-entry).

## `vite.config.ts`

The build config. Enables React Compiler, Tailwind v4, the Cloudflare plugin, and `decoVitePlugin()`. The dedupe list prevents duplicate copies of `react`, `@tanstack/*`, and `@decocms/*` from sneaking into the bundle.

See [Vite plugin reference](/v2/en/framework/vite-plugin).

## `wrangler.jsonc`

The Cloudflare deploy config. The minimum to know:

```jsonc
{
  "main": "./src/worker-entry.ts",
  "compatibility_date": "2026-02-14",
  "compatibility_flags": [
    "nodejs_compat",
    "no_handle_cross_request_promise_resolution"
  ]
}
```

The `no_handle_cross_request_promise_resolution` flag is required for deferred section rendering to work in dev mode under the Cloudflare Vite plugin.

See [Cloudflare Workers deployment](/v2/en/deployment/cloudflare-workers).
