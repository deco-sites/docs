This page walks you from zero to a deployed v2 storefront. The fastest path right now is to **clone a minimal reference site** and customize from there — a dedicated `npm create deco` is on the roadmap but not shipping yet.

<Callout type="info">
**Prerequisites:** Node.js 20+, a package manager (`npm`, `pnpm`, or `bun`), a Cloudflare account, and (optionally) a VTEX or Shopify store if you want commerce.
</Callout>

## 1. Clone a reference site

The cleanest starting point is **Le biscuit** — the most "spine-like" of the three reference stores. It uses every framework default without heavy customization.

```bash
git clone https://github.com/deco-sites/lebiscuit-tanstack my-store
cd my-store
rm -rf .git node_modules
git init
```

If you want a richer baseline (analytics wiring, Sentry, Firebase, regional fetch), use **Casa&Video** as the source — but expect to delete more code.

## 2. Install dependencies

```bash
npm install
```

Peer dependencies that need to be present (already pinned in the reference `package.json`):

- `@decocms/start ^2.28`
- `@decocms/apps ^1.11`
- `@tanstack/react-start ^1.166`
- `react ^19`, `react-dom ^19`
- `vite ^6`
- `wrangler ^4`

## 3. Point at your own decofile

Each site needs its own `siteName` and `.deco/blocks/` content. The CMS keeps content in two places:

1. **`.deco/blocks/*.json`** — committed source of truth. Edit through `admin.deco.cx`, sync to disk via the daemon.
2. **`src/server/cms/blocks.gen.json`** — generated bundle the framework loads at runtime.

Update the site identifier in [`src/setup.ts`](/Users/fernandofrizzatti/development/workspace/decocms/lebiscuit-tanstack/src/setup.ts) and in `cmsRouteConfig({ siteName: "your-site" })` inside `src/routes/$.tsx` and `src/routes/index.tsx`.

Then regenerate the bundle:

```bash
npm run generate:blocks
```

## 4. Configure commerce (optional)

If your store uses VTEX or Shopify, set up the matching configuration block in admin (or directly in `.deco/blocks/`). VTEX needs `account` plus `appKey`/`appToken` secrets; Shopify needs `storeName` plus a Storefront access token. See [Commerce overview](/v2/en/commerce/overview).

## 5. Run the dev server

```bash
npm run dev
```

Vite serves the storefront on `http://localhost:5173` (or whatever `PORT` you set). The first request triggers the daemon tunnel that keeps `admin.deco.cx` in sync with your local site.

## 6. Generate types and routes

After editing sections, blocks, or routes, regenerate the supporting files:

```bash
npm run generate:blocks   # blocks.gen.json
npm run generate:schema   # JSON Schema for the admin UI
npx tsr generate          # TanStack Router types
```

The reference sites' `package.json` exposes these as composite scripts; consult [`lebiscuit-tanstack/package.json`](/Users/fernandofrizzatti/development/workspace/decocms/lebiscuit-tanstack/package.json) for the canonical wiring.

## 7. Deploy to Cloudflare Workers

```bash
npx wrangler deploy
```

You need a `wrangler.jsonc` with:

```jsonc
{
  "name": "my-store",
  "main": "./src/worker-entry.ts",
  "compatibility_date": "2026-02-14",
  "compatibility_flags": ["nodejs_compat", "no_handle_cross_request_promise_resolution"]
}
```

Set secrets via `wrangler secret put` or the Cloudflare dashboard. See [Cloudflare Workers deployment](/v2/en/deployment/cloudflare-workers) for KV bindings, observability, and production checklists.

## What you get out of the box

Cloning a reference site already wires up:

- The Vite + Cloudflare + TanStack Start build pipeline ([`vite.config.ts`](/Users/fernandofrizzatti/development/workspace/decocms/lebiscuit-tanstack/vite.config.ts)).
- The Worker entry with admin routes and edge caching ([`src/worker-entry.ts`](/Users/fernandofrizzatti/development/workspace/decocms/lebiscuit-tanstack/src/worker-entry.ts)).
- Site setup with sections glob, blocks, matchers, and platform init ([`src/setup.ts`](/Users/fernandofrizzatti/development/workspace/decocms/lebiscuit-tanstack/src/setup.ts)).
- The CMS catch-all + home route via `cmsRouteConfig` / `cmsHomeRouteConfig`.
- Generated `blocks.gen.ts`, `sections.gen.ts`, `meta.gen.json`, `loaders.gen.ts`.

You can rip and replace at your own pace.
