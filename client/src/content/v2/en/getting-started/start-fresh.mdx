This page walks you from zero to a deployed v2 storefront by hand-creating the minimum set of files that `@decocms/start` and `@decocms/apps` need to boot.

<Callout type="info">
**A scaffold command is coming soon.** A dedicated `npm create deco@v2` (or equivalent) is on the roadmap and will collapse all of these steps into a single prompt. Until it ships, the manual recipe below is the supported path.
</Callout>

<Callout type="info">
**Prerequisites:** Node.js 20+, a package manager (`npm`, `pnpm`, or `bun`), a Cloudflare account, and (optionally) a VTEX or Shopify store if you want commerce.
</Callout>

## 1. Create the project

```bash
mkdir my-store && cd my-store
npm init -y
git init
```

## 2. Install dependencies

```bash
npm install \
  @decocms/start \
  @decocms/apps \
  @tanstack/react-start @tanstack/react-router \
  react@^19 react-dom@^19

npm install -D \
  vite@^6 \
  wrangler@^4 \
  typescript \
  @cloudflare/workers-types
```

The two deco packages are versioned independently. Pin to the latest published versions:

- `@decocms/start ^2.x` — framework + CMS bridge.
- `@decocms/apps ^1.x` — commerce integrations (VTEX, Shopify, Resend).

## 3. Add the build files

`vite.config.ts`:

```ts
import { defineConfig } from "vite";
import { cloudflare } from "@cloudflare/vite-plugin";
import { tanstackStart } from "@tanstack/react-start/plugin/vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";
import { decoVitePlugin } from "@decocms/start/sdk/vitePlugin";

export default defineConfig({
  plugins: [
    cloudflare(),
    tanstackStart({ target: "cloudflare-module" }),
    react(),
    tailwindcss(),
    decoVitePlugin(),
  ],
});
```

`wrangler.jsonc`:

```jsonc
{
  "name": "my-store",
  "main": "./src/worker-entry.ts",
  "compatibility_date": "2026-02-14",
  "compatibility_flags": ["nodejs_compat", "no_handle_cross_request_promise_resolution"]
}
```

## 4. Wire the framework

`src/setup.ts` — the central configuration. It must run **before** any module imports your sections, loaders, or matchers:

```ts
import { createSiteSetup } from "@decocms/start/setup";
import { autoconfigApps } from "@decocms/start/apps";

export const setup = createSiteSetup({
  siteName: "my-store",
  sectionsGlob: import.meta.glob("./sections/**/*.tsx", { eager: true }),
  apps: autoconfigApps(),
});
```

`src/worker-entry.ts` — the outermost layer of the Worker. **`import "./setup"` must be the very first line:**

```ts
import "./setup";

import { createDecoWorkerEntry } from "@decocms/start/sdk/workerEntry";
import {
  handleMeta,
  handleDecofile,
  handleRender,
  handleInvoke,
} from "@decocms/start/admin";
import serverEntry from "./server";

export default createDecoWorkerEntry(serverEntry, {
  admin: { handleMeta, handleDecofile, handleRender, handleInvoke },
});
```

`src/server.ts` — the TanStack Start server entry. Also imports `./setup` first:

```ts
import "./setup";
import { createServerEntry } from "@tanstack/react-start/server";
import { createRouter } from "./router";

export default createServerEntry({ createRouter });
```

## 5. Add the CMS routes

`src/routes/__root.tsx` — the global shell:

```tsx
import { DecoRootLayout } from "@decocms/start/hooks";
import { createRootRouteWithContext, Outlet } from "@tanstack/react-router";

export const Route = createRootRouteWithContext()({
  component: () => (
    <DecoRootLayout>
      <Outlet />
    </DecoRootLayout>
  ),
});
```

`src/routes/index.tsx` — the homepage, wired to the CMS:

```tsx
import { createFileRoute } from "@tanstack/react-router";
import { cmsHomeRouteConfig } from "@decocms/start/routes";

export const Route = createFileRoute("/")(
  cmsHomeRouteConfig({ siteName: "my-store" }),
);
```

`src/routes/$.tsx` — the catch-all for every other CMS-driven URL:

```tsx
import { createFileRoute } from "@tanstack/react-router";
import { cmsRouteConfig } from "@decocms/start/routes";

export const Route = createFileRoute("/$")(
  cmsRouteConfig({
    siteName: "my-store",
    ignoreSearchParams: ["skuId"],
  }),
);
```

`src/router.ts` — wires TanStack Router's generated route tree:

```ts
import { createRouter as createTanStackRouter } from "@tanstack/react-router";
import { routeTree } from "./routeTree.gen";

export const createRouter = () =>
  createTanStackRouter({ routeTree });
```

## 6. Connect the CMS

Each site needs its own `siteName` and `.deco/blocks/` content. The CMS keeps content in two places:

1. **`.deco/blocks/*.json`** — committed source of truth. Edit through `admin.deco.cx`, sync to disk via the daemon.
2. **`src/server/cms/blocks.gen.json`** — generated bundle the framework loads at runtime.

Provision the site in `admin.deco.cx`, point it at your local dev server with the daemon, and pull the initial `.deco/blocks/` content. Then generate the bundle the first time:

```bash
npx deco generate-blocks
```

(The command name and exact wiring are stabilizing; check the [framework reference](/v2/en/framework/overview) for the current scripts.)

## 7. Configure commerce (optional)

If your store uses VTEX or Shopify, set up the matching configuration block in admin (or directly in `.deco/blocks/`).

- **VTEX** — needs `account` plus `appKey` / `appToken` secrets.
- **Shopify** — needs `storeName` plus a Storefront access token.

See [Commerce overview](/v2/en/commerce/overview).

## 8. Run the dev server

```bash
npx vite dev
```

Vite serves the storefront on `http://localhost:5173` (or whatever `PORT` you set). The first request triggers the daemon tunnel that keeps `admin.deco.cx` in sync with your local site.

## 9. Deploy to Cloudflare Workers

```bash
npx vite build
npx wrangler deploy
```

Set secrets via `wrangler secret put` or the Cloudflare dashboard. See [Cloudflare Workers deployment](/v2/en/deployment/cloudflare-workers) for KV bindings, observability, and production checklists.

## What you get out of the box

Wiring the files above gives you:

- The Vite + Cloudflare + TanStack Start build pipeline.
- A Worker entry with admin routes and edge caching.
- Site setup with sections glob, blocks, matchers, and platform init.
- A CMS catch-all + home route via `cmsRouteConfig` / `cmsHomeRouteConfig`.
- Generated `blocks.gen.ts`, `sections.gen.ts`, `meta.gen.json`, `loaders.gen.ts` (after the first generate run).

You can then rip and replace at your own pace.
