`@decocms/apps-vtex/loaders/*` and `@decocms/apps-vtex/actions/*` are the server-side surface for VTEX. Loaders read; actions mutate. Both run inside the `RequestContext` with cookie propagation, instrumented fetch, and tracing.

## Loaders

Imported individually or via the barrel `@decocms/apps-vtex/loaders`:

```ts
import { searchProducts, getCart, getUser } from "@decocms/apps-vtex/loaders";
```

## Actions

Imported via the barrel:

```ts
import {
  getOrCreateCart,
  addItemsToCart,
  classicSignIn,
  notifyMe,
} from "@decocms/apps-vtex/actions";
```

`analytics/sendEvent` is a separate subpath: `@decocms/apps-vtex/actions/analytics/sendEvent`.

### `checkout` (cart)

| Function | Purpose |
|---|---|
| `getOrCreateCart()` | Create or fetch the user's cart (orderForm) |
| `addItemsToCart({ items })` | Add SKUs |
| `updateCartItems({ items })` | Update quantities, remove (qty 0) |
| `addCoupons({ coupon })` | Apply a coupon |
| `removeCoupons()` | Remove all coupons |
| `simulate({ items, country, postalCode })` | Shipping/price simulation |
| `getInstallments()` | Installment options |
| `getShippingByPostalCode({ postalCode })` | Shipping calculation |
| `addAttachment(...)`, `addOffering(...)`, `addProfileToOrderForm(...)` | Various orderForm mutations |

All return an `OrderForm`. They use **`vtexFetchWithCookies`** to ensure cookies round-trip correctly.

### `auth`

| Function | Purpose |
|---|---|
| `startAuthentication()` | Begin auth flow |
| `classicSignIn({ email, password })` | Email + password |
| `accessKeySignIn({ email, accessKey })` | Email + magic link code |
| `logout()` | Log out |
| `refreshToken()` | Token refresh |
| `recoverPassword({ email })` | Password recovery |

### `session`

| Function | Purpose |
|---|---|
| `createSession()` | Bootstrap a session cookie |
| `editSession({ items })` | Update session attributes (country, postal code) |
| `deleteSession()` | Tear down |

### `profile` & `address`

CRUD for the customer profile and address book. `*FromRequest` variants pull cookie/auth from the inbound request automatically.

### `wishlist`

| Function | Purpose |
|---|---|
| `addItem({ productId, sku })` | Add to wishlist |
| `removeItem({ id })` | Remove from wishlist |

### `masterData`

CRUD for VTEX MasterData documents (search, get, save, delete, attach files).

### `newsletter`

| Function | Purpose |
|---|---|
| `subscribe({ email })` / similar | Newsletter opt-in flows |

### `orders`

| Function | Purpose |
|---|---|
| `cancelOrder({ orderId, reason })` | Cancel an order |

### `misc`

Catch-all module: `notifyMe` (back-in-stock notifications), reviews, payment token deletes, and a few small utilities. See `vtex/actions/misc.ts` for the full list.

### `analytics/sendEvent`

```ts
import sendEvent from "@decocms/apps-vtex/actions/analytics/sendEvent";
```

POSTs to VTEX analytics endpoints from the server side (so cookies and request context are correct). Use sparingly — most analytics is fine to send client-side.

## Cookie semantics

Many actions (especially checkout, auth, session) use `vtexFetchWithCookies` from `vtex/client.ts`:

- Forwards inbound request cookies to upstream VTEX.
- Merges upstream `Set-Cookie` onto the response so the browser receives session/cart cookies.
- **Strips** `vtex_is_session` / `vtex_is_anonymous` so middleware controls IS cookies (avoids cache key explosion).

If you write your own cart-related action, use `vtexFetchWithCookies`, not raw `vtexFetch`.
