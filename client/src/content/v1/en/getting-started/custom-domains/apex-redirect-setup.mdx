## What is an Apex Redirect?

An apex domain is the root domain without any subdomain — `example.com` rather than `www.example.com`. Because DNS does not allow CNAME records at the apex, pointing the root domain to a CDN or load balancer requires fixed IP addresses via `A` records.

Deco provides a managed apex redirect service that:

- Accepts traffic on three static IPs (one per availability zone)
- Provisions a TLS certificate automatically via Let's Encrypt
- Returns a `301 Moved Permanently` to `https://www.<your-domain>` (or any subdomain you configure)

<Callout type="info">
  The apex redirect only redirects — it does not serve your site. Your site
  continues to run on the `www` (or other) subdomain.
</Callout>

## Setting Up a New Apex Redirect

### 1. Add the domain in the admin

In your site's control panel, go to **Settings → Domains** and click **Add existing domain**.

Enter the apex domain without any subdomain (e.g. `example.com`).

On the next step, set the redirect subdomain (e.g. `www`). Confirming this step provisions the redirect and issues a TLS certificate.

### 2. Configure DNS

Add three `A` records at your DNS provider, pointing the apex (`@`) to the following IPs:

| Record | Type | Value |
|--------|------|-------|
| `@` | A | `16.148.147.194` |
| `@` | A | `52.32.122.94` |
| `@` | A | `52.35.156.199` |

> **Note:** `@` represents the apex (root) domain. Some DNS providers use the full domain name or leave this field blank — check your provider's documentation.

### 3. Wait for the certificate

After DNS propagates, Let's Encrypt validates the domain and issues the TLS certificate. The entry in **Settings → Domains** shows **Active** once the certificate is ready. This usually takes a few minutes but can take up to an hour depending on DNS propagation.

## Migrating from the Legacy System

<Callout type="warning">
  If you see a "Legacy redirect detected" banner in the admin, one or more
  redirect domains on your site are still using the old system and need to be
  migrated.
</Callout>

The migration is zero-downtime: the new redirect is provisioned alongside the legacy one before you cut DNS over.

**Step 1 — Re-add the domain**

In **Settings → Domains**, click **Add existing domain** and enter the same apex domain again (e.g. `example.com`). Set the redirect subdomain on the next step and confirm. A new entry appears alongside the existing legacy entry.

**Step 2 — Update DNS**

At your DNS provider, replace any existing apex records with the three new IPs shown above. The old system used different IP addresses; once you point to the new ones the new redirect service takes over.

**Step 3 — Delete the legacy entry**

Wait until the new entry shows **Active** in the status column. This confirms the certificate has been issued and the redirect is serving traffic. Then open the `…` menu on the **old** entry and choose **Delete**.

<Callout type="info">
  The migration is only complete after DNS propagates. Do not delete the legacy
  entry before the new one is Active.
</Callout>

---

## Verification

After DNS propagates and the status shows **Active**, you can verify the redirect:

```bash
curl -si https://example.com/
# Expected: HTTP/2 301
# Location: https://www.example.com/
```

## Troubleshooting

**Status stays "Awaiting" for a long time**

- Confirm the three `A` records are set correctly at your DNS provider.
- DNS propagation can take up to 48 hours in some cases.
- Let's Encrypt uses an HTTP-01 challenge: it needs to reach your apex domain via port 80 before it can issue the certificate.

**Both old and new entries exist**

This is expected during migration. Keep both until the new entry is Active, then delete the old one.
